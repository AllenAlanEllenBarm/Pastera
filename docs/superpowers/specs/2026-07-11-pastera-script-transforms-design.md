# Pastera 脚本转换功能设计

## 背景与目标

Pastera 路线图已经记录“脚本功能”，目标是让用户通过本地 JavaScript 处理剪贴板文本，覆盖复制后自动转换、粘贴前转换和手动快捷键转换三类常用流程。

本设计参考 OneClip 公开仓库对脚本系统的功能描述，以及用户提供的脚本列表、新建脚本、快捷键和测试界面截图。OneClip 公开仓库没有包含截图所示脚本中心、JavaScript 执行器和快捷键实现，因此 Pastera 只参考其外部行为和信息层级，按照现有 AppKit、SQLiteData、`ClipService`、`PasteService`、`HotKeyService` 与设置中心架构独立实现。

成功标准：用户可以创建、编辑、启停和删除多个本地文本转换脚本；脚本可以在选定时机安全执行；执行失败不会破坏原剪贴板、产生递归监听或阻断正常粘贴。

## v1 范围

### 包含

- 设置中心新增“脚本”页面，显示脚本列表、状态、新建、编辑和删除入口。
- 支持多个脚本，按用户可调整的顺序执行所有满足当前触发条件的启用脚本。
- 脚本字段：稳定 ID、名称、代码、启用状态、复制时执行、粘贴时执行、手动执行时参与、排序值、创建时间、更新时间。
- 使用 JavaScriptCore 执行 `transform(clip)`。
- 支持复制后自动转换并写回剪贴板。
- 支持 Pastera 发起粘贴前转换，并把转换结果粘贴到原前台应用。
- 支持一个可配置的全局“执行脚本”快捷键；触发后读取当前剪贴板、执行脚本并把结果写回剪贴板，不自动发送粘贴键。
- 编辑器提供输入文本、运行测试、结果或错误展示。
- 简体中文和英文界面文案进入现有字符串目录；其他现有语言使用英文回退。

### 不包含

- `fetchSync()`、HTTP 请求或其他网络访问。
- 文件系统、Shell、进程启动、原生 Objective-C/Swift 对象桥接或任意系统 API。
- 图片、文件、音频、视频、富文本结构转换。
- OneClip 的免费版限制、付费提示、AI 生成脚本区域。
- 模板市场、在线模板、脚本导入导出和云同步。
- 截图中的全局复制、全局粘贴、应用内复制、应用内粘贴四套独立快捷键。

## 用户体验

### 脚本页面

“脚本”作为设置中心中的独立页面，视觉复用 Pastera 当前侧栏、分组卡片、按钮、开关和快捷键录制控件。空状态提供“新建脚本”；有数据时，每一行显示名称、启用状态、触发方式摘要、编辑和删除操作。页面提供统一的手动执行快捷键设置。

不照搬 OneClip 的商业横幅、紫色 AI 区域或一比一视觉尺寸。界面目标是让脚本能力自然融入 Pastera，而不是在应用中嵌入另一套设置中心。

### 新建与编辑

编辑器使用独立 AppKit 窗口或 sheet，包含：

1. 脚本名称。
2. 总启用开关。
3. 三个触发选项：复制时、粘贴时、手动执行时。
4. 等宽字体 JavaScript 编辑区。
5. 测试输入、运行测试、输出或错误区域。
6. 取消与保存按钮。

新建脚本预填最小可运行示例：

```javascript
function transform(clip) {
    return clip.text;
}
```

名称非空、至少选择一种触发方式、代码通过语法检查且存在可调用的 `transform` 后才能保存。编辑现有脚本时，取消不会写入草稿。

### 删除与错误反馈

删除脚本使用现有 Pastera 确认面板。运行测试时错误显示在编辑器内；后台自动执行失败时保留原文本，并发送不包含剪贴板内容和脚本源码的本地通知或应用内错误提示。相同脚本错误在短时间内合并提示，避免复制监听持续弹窗。

## JavaScript 合约与执行模型

### 输入输出

每次执行创建全新的 `JSContext`，只注入一个普通只读数据对象：

```javascript
{
  text: "当前纯文本",
  sourceAppBundleIdentifier: "com.example.app" // 无法确定时为 null
}
```

调用约定为 `transform(clip)`。返回值必须是字符串；空字符串是有效结果。未定义函数、JavaScript 异常、非字符串结果和超时均视为失败。

不同脚本按排序值串行组成转换管线：第一个脚本的字符串输出成为下一个脚本的 `clip.text`。任一脚本失败时，整次转换失败并回退到执行前的原始文本，不提交部分转换结果。

### 隔离和资源边界

- 不向 `JSContext` 暴露 `fetch`、`XMLHttpRequest`、`require`、文件、Shell 或原生对象。
- 执行在专用串行队列，避免阻塞主线程。
- 单脚本设置短执行期限；期限到达后丢弃该次上下文和结果。JavaScriptCore 无法安全终止的执行不得永久占用后续任务，因此执行器需要使用可回收的隔离工作单元，并限制同时存在的超时工作单元数量。
- 限制脚本源码和输入文本大小，避免异常内存增长；达到边界时显式报错而非截断内容。
- 日志只记录脚本 ID、错误类别和耗时，不记录脚本源码、输入或输出内容。

## 数据与组件边界

### 持久化

脚本使用 SQLiteData 新表持久化，遵循现有 schema 和 migrator 版本机制。新建 `ScriptRepository` 协议和实现，负责列表、读取、插入、更新、删除和排序；UI、执行器和快捷键不得直接操作数据库。

脚本属于本机自动化配置，v1 不进入 OneDrive 同步协议。数据库迁移必须保留现有历史、片段、OCR 和密码箱数据。

### 组件

- `ScriptTransform`：脚本领域模型和触发方式。
- `ScriptRepository`：持久化边界。
- `ScriptExecutionService`：JavaScript 合约、隔离、超时、管线和错误映射。
- `ClipboardScriptCoordinator`：根据复制、粘贴或手动触发加载脚本并协调剪贴板写回。
- `CPYScriptsPreferenceViewController`：列表、空状态和快捷键设置。
- 脚本编辑器控制器：表单、代码编辑、测试和保存校验。
- `HotKeyService`：注册唯一的手动执行全局快捷键，并把事件交给 coordinator。

依赖通过现有 `AppEnvironment` 注入，测试使用内存仓库和受控执行器替身。

## 业务数据流

### 复制时执行

1. `ClipService` 识别新的剪贴板内容。
2. 仅当内容具有纯文本且存在启用的“复制时执行”脚本时交给 coordinator。
3. coordinator 执行完整管线。
4. 成功后一次性把最终文本写回系统剪贴板，并让后续历史捕获以最终文本为准。
5. 写回携带进程内抑制标记和预期 change count，下一次监听识别为 Pastera 自身转换结果，避免再次执行。
6. 失败时不写回，原始剪贴板继续走现有历史保存流程。

### 粘贴时执行

1. 用户从 Pastera 历史、片段或当前剪贴板发起粘贴。
2. `PasteService` 在写入目标粘贴板之后、发送系统粘贴事件之前请求转换。
3. 成功时把最终纯文本作为该次粘贴负载；失败时使用原始负载继续粘贴。
4. 只影响 Pastera 主动发起的粘贴，不拦截系统级 `⌘V`。

### 手动执行

1. `HotKeyService` 收到全局快捷键。
2. coordinator 读取当前纯文本并执行所有启用且参与手动执行的脚本。
3. 成功时写回剪贴板，不自动粘贴；失败时保持原值。

## 兼容性和失败语义

- 没有脚本或没有匹配触发方式时，复制和粘贴行为与当前版本完全一致。
- 非文本剪贴板跳过脚本，不修改多格式数据。
- 自动复制转换后的历史仅保存最终文本，避免同时出现原始项和转换项。
- 粘贴转换只改变该次写入的纯文本，不永久修改已有历史记录。
- 脚本变更后立即影响下一次触发；正在执行的任务使用开始时的不可变快照。
- 全局快捷键冲突时沿用现有快捷键录制错误样式，不静默覆盖其他 Pastera 快捷键。
- 应用退出时不等待无限脚本；未完成结果被丢弃。

## 验收与验证映射

### 自动化验证（Codex）

- 数据库迁移在已有数据库和全新数据库上均成功，现有表数据不丢失。
- repository 支持 CRUD、稳定排序与触发条件查询。
- 执行器覆盖成功、空字符串、多脚本串联、语法错误、缺少函数、抛出异常、非字符串结果、输入边界和超时。
- coordinator 覆盖复制成功/失败、循环抑制、非文本跳过、粘贴成功/回退和手动执行。
- `HotKeyService` 覆盖注册、修改、清除、冲突与远程控制暂停/恢复。
- 设置目录、搜索、页面创建、空状态、表单校验、测试运行和删除确认有针对性测试。
- `git diff --check`、本地化 JSON 校验和完整 `xcodebuild clean test` 通过。

### 运行验证（Codex）

- 运行本地安装脚本替换 `/Applications/Pastera.app`，验证签名和真实进程。
- 在安装后的应用中创建大写转换脚本，验证测试区输出。
- 验证复制时转换只产生一个最终历史项。
- 验证从历史粘贴时转换文本并回到原前台应用。
- 验证全局快捷键只更新剪贴板、不自动粘贴。
- 验证禁用脚本后现有复制、历史和粘贴行为恢复不变。

### 人工体验验收（用户）

- 确认脚本页面、编辑器密度和深浅色表现符合 Pastera 设置中心体验。
- 确认常用真实脚本在目标应用中的复制与粘贴体验。

## 实现顺序

1. 增加模型、SQLite schema/migration、repository 和测试。
2. 以测试驱动实现 JavaScript 执行服务及安全边界。
3. 接入复制、粘贴、手动快捷键数据流和循环抑制。
4. 增加设置页面、编辑器、测试区、本地化和偏好搜索。
5. 执行针对性测试、完整构建、安装与真实运行验收。

## 风险

- JavaScript 无限循环和资源消耗是最高风险，实现计划必须在编码前验证 JavaScriptCore 可用的终止机制；若当前 macOS SDK 无法可靠终止，执行器应采用可回收隔离工作单元并设置并发上限，不能用主线程定时器伪装成安全超时。
- 复制监听写回容易产生递归或双历史项，必须以 change count 和明确来源状态验证完整时序。
- 当前工作区包含未提交的设置中心、密码箱和 OCR 改动。实现只扩展相关链路，禁止覆盖、重排或清理用户已有修改。
