# Open Collective Funding Plan

Pastera has applied for Open Source Collective fiscal hosting so the project can
receive and spend funds transparently for open-source maintenance.

## Why Funding Is Needed

The current public beta can be built and distributed without paid infrastructure,
but trusted macOS distribution requires Apple Developer Program membership,
Developer ID signing, notarization, and release maintenance. Without that path,
users may need to manually approve unsigned beta builds in macOS Gatekeeper.

Funding helps the project move from unsigned beta releases toward a safer public
installation experience.

## Intended Spending

Project funds may be used for:

- Apple Developer Program membership.
- Developer ID signing and notarization setup.
- Release infrastructure and artifact hosting.
- Build, test, and compatibility hardware or services.
- Design assets, documentation, localization, and project maintenance.
- Reimbursement for approved project work.

Funds should not be used for unrelated personal expenses, private app services,
or credential sharing arrangements.

## Transparency

If fiscal hosting is approved, expenses should be submitted through Open
Collective with a clear public description of the project need. Large or unusual
expenses should be discussed in a GitHub issue before reimbursement.

## Relationship To Apple Signing

Fiscal hosting does not automatically grant Apple Developer ID certificates.
The project still needs a compliant Apple Developer Program path. Funds may be
used to pay for that membership or related release operations if the fiscal host
allows it.

Pastera will not rent, buy, or share third-party Developer ID certificates from
untrusted parties.
