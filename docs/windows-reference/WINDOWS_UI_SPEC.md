# Windows V1 界面与交互规格

## 设计目标

Windows 客户端保持 Pastera 的高频、键盘优先、紧凑和低打扰特性。它使用
Windows 11 原生系统 chrome、控件绘制和平台术语，但产品内容区必须看起来仍是
同一个 Pastera 页面，不能以“Windows 原生”为理由重新设计信息架构。

截图是内容区主验收基准。文字规格解释行为、安全和平台替换；来源更新且状态
匹配的截图决定内容区结构、区域位置、顺序、尺寸、间距和信息密度。

## 截图验收门

### 内容区几何容差

在相同业务状态、主题和归一化内容区尺寸下：

- 主区域、导航、工具栏和底部模式栏每条边相差不超过 `8 epx`。
- 相邻控件、卡片、分组和列表行间距相差不超过 `4 epx`。
- 同类控件和列表行高度相差不超过 `4 epx`。
- 内容区宽高比变化不超过 `3%`。
- 固定视口可见列表行数应一致；系统字体度量最多相差一行并记录。
- 文案换行、截断、主按钮位置和空状态中心不能出现新的视觉断层。

`epx` 是归一化到 100% DPI 内容区后的有效像素。

### 差异分级

- `P0 结构偏差`：入口缺失/移动、导航变化、页面合并/拆分、状态或主动作缺失。
  阻断完成。
- `P1 几何偏差`：区域、尺寸、间距、密度、可见行数或对齐超出容差。阻断完成。
- `P2 平台绘制差异`：系统标题栏、字体栅格化、系统图标笔画、焦点环和原生
  对话框细节。记录后可接受，但不得带动布局变化。
- `P3 动态内容差异`：时间、版本、合成记录正文等。比较时遮罩。

未获用户批准的 P0/P1 必须为 0。

### 三联证据

每个 UI 状态必须提交：

1. 来源明确的 macOS 参考图。
2. 相同业务状态、主题和内容区尺寸的 Windows 11 图。
3. 排除系统 chrome 和 P3 动态内容后的 50% 透明叠加图。

没有三联图只能标记“待视觉验收”；仍有未获批准的 P0/P1 只能标记“截图验收
未通过”。构建成功、AutomationId 可查询或单元测试通过不能替代截图结论。

## 全局结构

### 托盘与主面板

- 通知区域图标左键打开主面板，右键打开应用菜单。
- 主面板为单实例无任务栏工具浮层；失焦关闭，但打开编辑器、文件选择器或
  子面板时不得误关。
- 顶部保留内容类型筛选和分页；底部保留搜索、历史、Snippet、密码箱、同步
  状态和设置入口。
- 默认内容区参考现有 300×356 / 300×398 基线图；Windows 系统 chrome 可以
  改变窗口外框，但归一化内容区宽高比不得超出 `3%`。
- 列表行保持紧凑，主点击区执行复制/粘贴，次级操作通过悬停按钮、右键菜单
  或键盘命令提供。
- 不得增加大卡片、营销式留白、无关标题区或额外底栏来替换参考图结构。

### 独立工作窗口

- 设置、历史搜索、Snippet 编辑器、历史编辑器和脚本编辑器使用正常可调整
  窗口并参与 Alt+Tab；托盘浮层不参与 Alt+Tab。
- 窗口位置和尺寸可恢复，但必须校正到当前显示器工作区。
- 危险操作使用 ContentDialog，并明确对象、影响范围和不可逆性。
- 系统标题栏可以使用 Windows 11 原生形式；标题栏下方的产品内容区仍按参考
  图和几何容差验收。

## 页面规格

### 历史与提示词优化

- 过滤类型至少覆盖全部、文本、图片、文档、压缩包、代码、PDF、其他。
- 搜索支持普通文本、Regex、大小写敏感；空查询显示最近历史。
- 行内显示类型、摘要、时间和必要预览；完整内容放在详情/预览区，不让长文本
  撑高列表。
- 编辑必须是显式动作，保存和取消清楚；删除后刷新筛选、分页和焦点位置。
- 提示词优化由用户显式触发；优化结果先进入草稿，可撤销且只有显式保存才
  覆盖历史。取消、超时、失败和无需修改都保留原文。
- 图片、文件和密码类内容不得在通知、日志或无意悬停中泄露完整内容。

### Snippet

- 浏览态和编辑态分离。浏览态用于搜索、选择和粘贴；编辑态提供文件夹树、
  条目详情、排序、移动、启停、导入与导出。
- `snippets/01-editor-empty-dark.jpg` 的顶部工具栏、左树、右详情和空态比例是
  内容区基准；小窗口可切换单列导航，但必须单独补图并取得用户确认。
- 空状态说明下一步，并只突出一个主动作。
- 导入先预览数量和冲突策略；导出明确文件位置与成功/失败结果。

### 密码箱

- 未创建：创建主密码并二次确认；提示忘记主密码无法恢复。
- 已锁定：主密码解锁为标准路径；Windows Hello 可在已经成功解锁并明确启用后
  作为便利入口，不能取代 KDBX 主密码。
- 已解锁：文件夹、条目列表和详情分区；密码默认隐藏，复制后提供短时反馈，
  自动锁定状态可见。
- 主密码变更和 rekey 必须显示校验、进行中、成功和可恢复失败。
- Agent 集成必须显示未安装、授权中、已授权、撤销和失败状态；不能显示或返回
  主密码和明文密码。
- 认证失败使用就地错误，不清空用户仍需修正的输入；不得记录主密码、明文密码
  或完整用户名。

### 密码箱 OneDrive 同步

- UI 必须区分 OneDrive 客户端可用、本地 replica 已写入和云端上传/下载未知。
- 同步中、恢复、冲突、重建和失败是密码箱页面内的就地状态，不把同步错误伪装
  成密码箱被锁定。
- “同步完成”只能表示 Pastera 本地文件工作完成。

### 脚本

- 列表展示名称、启用状态和触发时机；编辑器使用等宽字体、行号和明确保存状态。
- 模板、编辑和测试入口必须保持在脚本页面，不拆成无法追踪的独立导航。
- 测试区输入与输出分开，错误包含安全的行列信息。
- UI 只能表达受限 `transform(clip)` 能力，不能暗示文件、网络、进程或系统访问。

### 设置

- 使用固定左侧分类导航。基线分类包括：基础设置、历史记录、脚本、快捷键、
  忽略应用、云同步、关于。
- `7b57094` 增量增加独立提示词优化、密码箱安全、Agent 集成和软件更新入口；
  具体顺序必须先由安全 macOS 参考图确认，缺图时不得自行重排。
- Windows 替换规则：登录时打开使用 StartupTask/启动设置；自动粘贴说明改为
  Windows 输入注入与权限限制；Finder 改为文件资源管理器；Command 改为
  Ctrl/Win/Alt；Sparkle 改为 Windows 更新通道。
- OneDrive 只选择本地 OneDrive 内可写目录，不出现 Microsoft 登录或 OAuth。
- 破坏性操作单独分组，不与普通开关混排。
- WinUI 默认 NavigationView 宽度、Header、Card 和间距不是改变 760×600
  基线信息密度的理由。

### 软件更新

- 使用独立设置页表达自动检查、手动检查、检查中、可更新、最新、错误和安装
  失败回退。
- 用户确认后才下载/安装/重启；签名或哈希失败必须阻断安装。
- Windows 不展示 Sparkle、DMG 或 macOS appcast 字段。

## 状态与反馈

每个页面至少实现：加载中、空、正常、部分不可用、操作中、成功、可恢复错误和
不可恢复错误。后台同步、提示词连接测试或更新使用非阻塞状态；需要用户处理时
使用 InfoBar，不能连续弹出模态框。

## 可访问性和键盘

- 所有动作均可通过键盘到达；Tab 顺序遵循视觉顺序，Esc 关闭浮层或取消编辑，
  Enter 执行当前主动作。
- 可见焦点环不得被自定义背景覆盖；图标按钮必须有 AutomationProperties.Name。
- 支持系统浅色、深色、高对比度、文本缩放和 100%/125%/150% DPI。
- 不只依赖颜色表达选择、错误、同步、锁定或授权状态。
- 可访问性适配可以改变系统绘制，但不能隐藏产品入口或打乱视觉顺序。
